SUPPLY-CHAIN RFT VS SFT SHOWCASE

The experiment compares available Foundry model/method packages, not training
methods on a common base model. The preregistered objective is for RFT to beat
SFT by at least 0.05 with a paired 95% bootstrap confidence interval above 0,
while avoiding output-pattern collapse. Raw o4-mini uplift cannot be measured
because Azure allows fine-tuning this deprecated model but not deploying it raw.

1. Install and validate locally:
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m pytest tests -q
   .\.venv\Scripts\python.exe preflight.py --count 50

2. Copy .env.example to .env and set real deployment/resource names. Raw base
   deployments are optional context arms. Do not substitute a different model
   as an o4-mini proxy when deprecated raw o4-mini cannot be deployed.

3. Run the billable 50-scenario go/no-go pilot:
   .\.venv\Scripts\python.exe 01_baseline_teacher/capture_pilot.py --count 50 --teacher-attempts 3 --confirm-paid
   .\.venv\Scripts\python.exe 01_baseline_teacher/analyze_pilot.py

   Stop if any gate fails. Do not weaken a failed gate after seeing results.

4. Capture fixed-budget teacher labels and build both datasets:
   .\.venv\Scripts\python.exe 01_baseline_teacher/capture_training.py --train 300 --valid 60 --teacher-attempts 3 --sft-threshold 0.75 --confirm-paid
   .\.venv\Scripts\python.exe 02_dataset_build/build_datasets.py
   .\.venv\Scripts\python.exe 03_finetuning/rft/build_grader.py

5. Submit jobs only after reviewing current Azure pricing and pilot evidence:
   .\.venv\Scripts\python.exe pre_submit_audit.py
   .\.venv\Scripts\python.exe 03_finetuning/rft/submit_rft_job.py --confirm-paid
   .\.venv\Scripts\python.exe 03_finetuning/sft/submit_sft_job.py --confirm-paid

6. Deploy each completed fine-tuned model:
   .\.venv\Scripts\python.exe 03_finetuning/deploy_finetuned_model.py MODEL_ID DEPLOYMENT_NAME --confirm-paid

7. Evaluate the required three references on the same 150 held-out scenarios:
   Review current Azure per-million-token rates for each deployment, then run:
   .\.venv\Scripts\python.exe 04_evaluation/evaluate.py --arm teacher=TEACHER_DEPLOYMENT --arm sft=SFT_DEPLOYMENT --arm rft=RFT_DEPLOYMENT --pricing teacher=INPUT_RATE,OUTPUT_RATE,CACHED_INPUT_RATE --pricing sft=INPUT_RATE,OUTPUT_RATE,CACHED_INPUT_RATE --pricing rft=INPUT_RATE,OUTPUT_RATE,CACHED_INPUT_RATE --count 150 --compare rft,sft --confirm-paid

   Generate the stepped quality/cost/latency hill-climb chart:
   .\.venv\Scripts\python.exe 04_evaluation/plot_step_hill_climb.py 04_evaluation/results/reasoning-hill-climb-20260725.json --output 04_evaluation/results/step-hill-climb-20260725.png

   Add raw_rft or raw_sft arms only when those exact raw deployments exist.

Do not claim that RFT is better unless the saved evaluation shows: RFT-SFT
mean >= 0.05, the paired CI excludes zero, and dominant_pattern_share and
all_defer_share remain below the frozen 0.80 collapse thresholds. Always report
that raw o4-mini uplift was unmeasurable due to deployment deprecation.
